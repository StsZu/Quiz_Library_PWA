# Конституція проєкту «Мої квізи» (бібліотека квізів, PWA)

Постійні правила. Порушення будь-якого пункту розділу **Non-negotiables** блокує приймання результату.
Погоджено 2026-10-30 разом із планом (`specs/001-quiz-library/plan.md` → «Погодження»). Шляхи `Creator_quiz/…` — відносно `/Users/szubar/Projects/Educational_courses_2026/`.

## I. Принципи

1. **Дані учня лишаються на пристрої.** Спроби, відповіді й помилки зберігаються лише в браузері (IndexedDB). Сервера, облікових записів, аналітики й сторонніх запитів немає. Перенесення між пристроями — тільки експорт та імпорт файлу.
2. **Квізи надходять із двох джерел.** **Вбудовані** — JSON в `Creator_quiz/OUTPUT_quiz/` зі списку курсів, що проходить `tools/build_quiz.py` з кодом `0`. **З диска** — файли формату `quiz-package` v1 (`Creator_quiz/schemas/quiz-package.v1.schema.json`) або обгортка Creator_quiz, які власник відкриває в застосунку. Застосунок не викликає моделей і не генерує питань сам. Ручне створення й редагування — лише для квізів з диска; вбудовані не редагуються. (Поправка 1.)
3. **Поведінка екрана квізу — як у шаблоні.** Еталон — `Creator_quiz/templates/quiz-md3.html` разом із вимогами spec 001 (FR-20…FR-31, NFR-01…NFR-08) і spec 002 (FR-20…FR-22). Кожна відмінність записується в `spec.md` → «Свідомі відхилення»; мовчазних відмінностей немає.
4. **iPad і iPhone у Safari — головна платформа.** Рішення приймаються за поведінкою встановленої PWA на iPadOS та iOS.
5. **Мінімум залежностей.** Runtime-залежності — лише `preact`, `@preact/signals`, `idb`. Нова залежність — лише з окремим обґрунтуванням у `plan.md`.

## II. Обмеження

- `Creator_quiz` для застосунку — лише читання: скрипт імпорту читає JSON і викликає `tools/build_quiz.py`, нічого там не змінюючи. Виняток — погоджені зміни формату в `Creator_quiz/schemas/`.
- У збірку потрапляють лише квізи з явного списку курсів (`content/courses.json`); приватні квізи (наприклад, `zubar-defense-interview-quiz`) не додаються.
- Квізи з диска зберігаються лише на пристрої (IndexedDB) і ніколи не потрапляють у `public/content/`, репозиторій чи збірку. (Поправка 1.)
- Копія схеми `quiz-package` у застосунку (`schemas/`) збігається з `Creator_quiz/schemas/` байт у байт; це перевіряє тест. Зміна формату — спершу в Creator_quiz. (Поправка 1.)
- Без секретів: ключів, токенів і облікових даних немає ні в репозиторії, ні в збірці.
- Створення репозиторію, push, розгортання на Cloudflare, налаштування Cloudflare Access — лише з окремим дозволом власника на кожну дію.
- Мова інтерфейсу застосунку — українська. Екран квізу використовує рядки мови квізу (spec 001, L-04).

## III. Пріоритети (при конфлікті вищий виграє)

1. Цілісність даних учня: спроби й помилки не губляться, імпорт не псує наявні дані.
2. Учень проходить квізи й повторює помилки офлайн на iPad.
3. Доступність і дизайн: не гірші за шаблон після виправлень `Creator_quiz/DESIGN_AUDIT.md`.
4. Розмір і швидкодія.
5. Інші браузери — найкраща можлива сумісність.

## IV. Стандарти якості

| Область | Стандарт |
|---|---|
| Мова | TypeScript `strict: true`; `tsc --noEmit` без помилок; ESLint без помилок |
| Логіка | Vitest; покриття `src/core/**` ≥ 85 % рядків; модульні тести без мережі |
| Інтерфейс | Playwright: WebKit «iPad Pro 11» і «iPhone 13», Chromium офлайн; e2e проходять 3 прогони поспіль |
| Екран квізу | `Creator_quiz/tools/audit_page.js` на 360×740, 1280×800 і iPad: `fails` і `warns` порожні |
| Доступність | WCAG 2.1 AA: контраст ≥ 4,5 : 1 (великий текст 3 : 1), зокрема невибраних варіантів; цілі дотику ≥ 48×48 px; видимий фокус; `aria-label` українською |
| PWA | Валідний `manifest.webmanifest`; service worker з precache застосунку й усього вмісту; іконки 180/192/512 без прозорості; запуск офлайн до бібліотеки й будь-якого квізу |
| Безпека | CSP `default-src 'self'` без сторонніх доменів у `index.html` і `_headers`; у мережевому журналі e2e немає запитів за межі власного origin |
| Розмір | JS після gzip ≤ 80 КБ без вмісту квізів |

## V. Non-negotiables

1. Жодних секретів у репозиторії, збірці чи артефактах перевірок.
2. Дані учня нікуди не надсилаються.
3. Імпорт прогресу й відкриття файлу квізу ніколи не змінюють наявні дані без підтвердження і не змінюють їх зовсім, якщо файл не пройшов перевірку. (Поправка 1.)
4. Спроба, завершена до перезавантаження чи закриття застосунку, після відкриття видна в бібліотеці.
5. У застосунок не потрапляє квіз, який не пройшов `build_quiz.py` з кодом `0` (вбудований) або ті самі правила, перевірені в браузері (з диска). Відповідність перевірок підтверджується спільними фікстурами (spec 002, SC-11). (Поправка 1.)
6. `Creator_quiz` лишається незмінним під час роботи над застосунком, крім окремо погоджених задач.

## VI. Процес

- Кожна задача має перевірний результат і умову Done; `[x]` лише з доказом.
- Не більше 3 спроб на задачу; далі — запис у `alignment.md`, продовження з незалежними задачами.
- Нова вимога чи зміна поведінки — спершу запис у `spec.md`, потім код.
